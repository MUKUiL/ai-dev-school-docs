## 概要・テーマ

クライアントより「社内文書をいい感じに検索したい」という依頼を受け、現状の困りごとと求める姿をヒアリングした。**ファイル名の一覧ではなく、根拠つきの回答**が欲しいというニーズが中心であることを確認した。副次的に、定例議事録の要約ニーズも共有されたが、**本案件の主軸は文書検索**とする。

## 会議の内容

### 1. 現状と課題感

- 社内ルール（経費・勤怠・開発ガイド等）の確認に、共有フォルダ探索（Ctrl+F）や Slack 質問が使われている
- Slack で聞けば分かる文化が定着し、**総務部・在籍の長いメンバーへの聞き返し負荷**が増えている
- ファイル名が分かっても結局開いて読む必要があり、**答えそのもの**が欲しい
- 回答には**根拠となった文書の提示**が必須。誤回答への不安が強い

### 2. 対象データ・利用イメージ

| 項目 | 内容 |
| --- | --- |
| 保管場所 | Google ドライブ共有フォルダ、GitHub（Markdown） |
| 形式 | Google ドキュメント、Markdown、PDF（規程類） |
| ファイル数 | 全体約200、**現役参照は30〜40**程度 |
| 利用者 | 全社約300名（特に中途入社者・総務部への問い合わせが多い部署） |
| 利用頻度 | 1日20〜30回程度（ピーク時はそれ以上の可能性） |
| Excel | 勤怠集計表等あり。**初版の必須対象外**（あれば望ましい） |

### 3. 技術・運用上の制約

- **給与フォルダは絶対に対象外**。対象文書は総務部が1件ずつ確認してリスト化
- 外部 LLM 等への送信は役員説明が必要。**何をどこに送るか**を文書化する
- ログに本文・個人情報を載せない（文字数・成功失敗等のメタ情報中心）
- API キーはサーバー側のみ（フロントに直書きしない）
- 予算は**月数千円**程度。超過前に相談。**上限設定**が必須条件
- 初版は**ログイン・ロール管理不要**。社内限定 URL で運用想定
- 文書更新は手動再取り込みで足りる（リアルタイム同期・Drive 自動同期は初版不要）

### 4. 品質・評価の方向性

- 精度100%は求めない。**根拠が無いときは「分からない」と返す**仕様で合意
- 評価は正答率ではなく、**根拠の有無とハンドリング**で設計する方針

### 5. 副次トピック（議事録要約）

- 定例議事録が長く、決定事項・ToDo の抽出ニーズあり
- **検索が主、議事録要約は余裕があれば**別トラックで小さく試作（貼り付けて要約程度）
- 開発定例のサンプルを情報システム部から提供可能

### 6. 未決・次回以降

- 公開 URL の制限方法（社内 VPN、限定公開、パスワード等）
- 障害時の連絡先・対応時間（夏休みの当番表確定後）
- Excel 連携、Drive 自動同期の初版以降の扱い

## 課題・決定したこと

### 課題（クライアント側の困りごと）

| # | 課題 |
| --- | --- |
| 1 | 社内ルールの確認に時間がかかる（測定値は未整備） |
| 2 | Slack への依存と、回答側の工数負荷 |
| 3 | キーワード検索では「答え」にならない |
| 4 | AI の誤回答・根拠不明回答への不安 |
| 5 | 外部サービス利用・個人情報・コストに対する社内説明・統制 |

### 決定事項

| # | 決定内容 |
| --- | --- |
| 1 | **依頼の核**は「社内ルールへの質問に、根拠つきで答える」こと |
| 2 | ファイル名検索のみでは不十分。回答＋根拠文書の提示が要件の中心 |
| 3 | 対象は現役 **30〜40ファイル**程度。給与・人事評価は除外 |
| 4 | 初版は**手動アップロード／再取り込み**、ログインなし |
| 5 | 外部送信一覧・ログ方針を要件に反映。本文はログに残さない |
| 6 | 月額**数千円・上限設定必須**。超過前相談 |
| 7 | 根拠が無いとき**回答を生成しない**仕様とする |
| 8 | **4月の中途入社（3名）前**の稼働が望ましい（超急ぎではない） |
| 9 | 文書検索が**主案件**。議事録要約は並行トラック（小さく試作） |
| 10 | 初版の公開範囲は**外部公開しない**（具体手段は次回） |
