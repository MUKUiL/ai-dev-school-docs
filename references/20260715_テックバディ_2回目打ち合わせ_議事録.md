## 会議の内容

### 1. 外部送信の社内合意（Q9）

- 経理・法務・役員との協議の結果、**利用合意が取れた**
- 条件は次の3点
  1. **給与・人事評価・個人情報を含む文書は対象外**
  2. **どの外部サービスに何を送るかを一覧にして提出**
  3. **送った内容をログに残さない**（質問文・回答本文をログから読めないこと）
- ログは成功／失敗・文字数などの**メタ情報中心**。API キーはログに載せない
- 送信一覧の提出形式は **Markdown 可**（情シスが GitHub で管理しやすい形式）

### 2. 現状の所要時間 ── 1週間実測（Q10）

| 探し方 | 件数 | 所要時間の中央値 |
| --- | --- | --- |
| 自分で共有フォルダを探した | 18件 | **6分** |
| Slack で聞いた | 11件 | **22分**（返信待ちを含む） |

- 回収元：総務部18件、開発部アンケート11件
- Slack 22分には**返信待ち・他業務の合間**が含まれるケースあり
- 実測中に「検索ツールが欲しい」という声あり。**期待値管理のため初版スコープを要件で固定**する方針
- 非機能要件・改善効果説明の**現状値**として要件定義に反映

### 3. 納期（Q11）

- **超急ぎではない**
- **2026年4月に中途入社3名**が入るため、**それまでに動いていると望ましい**
- 目安：**3月ベータ／4月本番**（スコープ確定後に詳細スケジュールを提示）
- 初版は**手動取り込み・ログインなし**前提で現実的なラインは見える、との受託側見解

### 4. 予算（Q12）

- **月数千円**程度なら承認可能。**超過前に必ず相談**
- **従量課金のみの契約は経理が嫌がる**ため、**使用上限（spend limit）の設定が必須条件**
- 埋め込み用に**別プロバイダが増える可能性**あり。送信一覧にすべて記載する（条件②）

### 5. 保留項目の初版スコープ整理

| 項目 | 2回目での合意 |
| --- | --- |
| Excel 集計表 | **初版対象外**（やらないことに明記）。ルール文書を優先 |
| Google ドライブ自動同期 | **初版は手動アップロード／再取り込み** |
| アクセス権限（ロール） | 全社員が読める文書のみ対象 → **初版はロール管理不要** |
| 対象文書リスト | **35件ドラフト**を総務部が1件ずつ確認済み。給与フォルダは含まない |
| 公開 URL の制限 | VPN 案を経営陣が納得しやすいと評価。在宅者向けに**限定公開＋パスワード併用**も検討。**詳細は設計フェーズ** |
| 障害時の連絡先・対応時間 | **未決**（夏休み当番表確定後・納品前に決定）。情シスは平日9〜18時対応が目安 |

### 6. 副次トピック（議事録要約）

- 開発定例向け**議事録要約の試作**をクライアントが確認。評価は良好
- **検索が主案件**の方針は維持。要約機能は**別トラック**・別画面でよい
- リソース配分は検索の要件確定後に協議

| 8 | 問い合わせは Slack ではなく**メール**（自社の Slack 依存を避けるため） |
| 9 | 議事録要約は**別トラック**のまま。検索要件を先に確定 |
