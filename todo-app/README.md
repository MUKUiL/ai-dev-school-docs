## Phase 1 でこれを何に使うか

Phase 1 の目的は **Vibe Coding（勢いで作る進め方）で作ってみて、どこで壊れるかを体験する**ことです。フレームワークの作法を身に付けることではありません。

そのため、このサンプルは「よく設計された模範解答」ではなく、**受講生が同じ手順で辿り着ける到達点**として置いてあります。

## 動かし方

### 静的版（`01-static/`・`01-static-solution/`）

**インストールは不要です。** `index.html` をブラウザで開けば動きます。

```bash
open 01-static/index.html
```

`file://` で開くのが気になる場合は、簡易サーバーでも構いません（Python があれば追加インストール不要）。

```bash
cd 01-static && python3 -m http.server 8000
# http://localhost:8000 を開く
```

### Next.js 版（`02-nextjs/` ・ `03-broken/`）

どちらも同じ手順です。作業するディレクトリに `cd` してから実行してください。

```bash
cd 02-nextjs       # 欠陥版の場合は cd 03-broken
npm install        # -g は付けない。この階層の node_modules にだけ入る
npm run dev        # http://localhost:3000
```

テストを走らせる場合（同じディレクトリ内で）。

```bash
npm test           # 02-nextjs は 23件すべて通る
                   # 03-broken は 7件落ちる（欠陥①②を検出する）
```

> **`npm install -g` は使いません。** 依存は各ディレクトリの `node_modules/` に入ります。`node_modules/` が既に同梱されている場合は `npm install` を省略できます。

### 検証中に見つけて直したもの

静的版の最初の実装は `String(Date.now())` で id を採番していました。**続けて追加すると同じミリ秒になり id が衝突**し、1件削除したつもりが2件消えます。

手で数回触るだけでは気づきにくく、E2E で初めて表面化しました。乱数を足す形に直し、`02-nextjs/tests/todos.test.ts` に**1000件の id が重複しないことを確かめるテスト**を残してあります。

これは `1-2-8` で扱う「動いているように見えて壊れている」の実例として、教材本文からも参照します。
