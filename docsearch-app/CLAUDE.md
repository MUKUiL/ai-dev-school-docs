# 社内文書検索アシスタント 開発ルール

このリポジトリでコーディングエージェントが作業するときのガードレール。
根拠と設定の解説は [docs/procedure/implementation.md](./docs/procedure/implementation.md) にある。

## 仕様

- `docs/spec.md`（受け入れ基準 F-1〜F-6）が**唯一の判断基準**。実装で迷ったら spec.md を参照し、書かれていないことは**推測せず、質問として報告する**。
- `docs/requirements.md` は背景の理解に使う。合否には使わない。
- 数値の根拠は `docs/notes/`（質問の上限・費用・評価セット・外部送信の一覧）にある。

## 設計の固定

- 構成（検索方式・プロバイダ・ベクトルストア）は `docs/adr/` の3本で**決定済み**。別の構成の提案・変更をしない。
- `docs/schema.sql` が DB 定義の正。実装側の都合で変えない。変更が必要になったら**止めて報告する**。

## 構成のルール

- SDK（`@anthropic-ai/sdk`・`openai`・`@supabase/supabase-js`）に触れるのは **`lib/providers.ts` だけ**。他の `lib/` は `lib/clients.ts` のインターフェースにだけ依存させる。
- `tests/` から `lib/providers.ts` と各 SDK を **import しない**。
- `corpus/`（対象文書35件）は**読み取り専用**。変更・追加・削除をしない。
- 部品は `lib/` に置き、1ファイル1責務にする。

## 変更の範囲

- タスクを始める前に、**変更するファイルの一覧**を出す。一覧に無いファイルは変更しない。
- 依頼された範囲を超える変更（似た箇所の一括修正・リファクタ）は、**提案として挙げるだけにして、実行しない**。
- 1タスクで **10 ファイル**を超える変更が必要になったら、止めて分割を提案する。

## 触ってはいけないもの

- **テストの削除**をしない。**期待値を緩めない。**テストが落ちたら、まず実装を疑う。
- `.env`・`.env.local` を読まない、書かない。
- `package.json` の依存を、**理由の説明なしに**追加・変更しない。
- `docs/` 配下（spec・requirements・adr・schema.sql・notes）を、実装に合わせて書き換えない。

## テストのルール

- **LLM の出力の文面を期待値にしたテストを書かない**（Constitution 第13条1）。判定してよいのは**形式**と、**根拠の実在**（`lib/verify.ts`）だけ。
- テストは `tests/fakes.ts` の偽物で完結させ、**外部を呼ばない**。

## 検証ループ

- 各タスクの終わりに `./scripts/verify`（型チェック＋テスト。**ラッパー経由でコンテナ内実行**）を実行し、**緑に戻してから**次へ進む。
- ホストに Node.js や `node_modules` は不要。判定器はコンテナ内で動く。素の `npm run …` をホストで実行しない。

## 費用の出る操作

- 取り込み（`./scripts/ingest`＝コンテナ内の `npm run ingest`）は**実行しない**（外部 API を呼び、費用が出る。実行は人がやる）。実行が必要だと判断したら、止めて報告する。

## 確認を挟むこと（実行前に何をするかを述べて、承認を待つ）

- ファイルの削除
- 依存パッケージの追加
- 環境変数・デプロイ設定の変更
- 外部 API を呼ぶ回数が増える変更（再試行回数・並列化）

## 停止条件（ここまで来たら手を止めて報告する）

- 同じエラーの修正を **3回**試して直らない
- 仕様（`docs/spec.md`）に書かれていない判断が必要になった
