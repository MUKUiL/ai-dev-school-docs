# リリース手順

> 株式会社テックバディ 情報システム部
> ※ 本書は架空の会社の架空の文書です。実在の企業・団体とは関係ありません。

## 1. リリース前

- [ ] 対象のプルリクエストがすべてマージされている
- [ ] 単体・統合テストが通っている
- [ ] 環境変数の追加・変更があれば、本番環境に反映済みである
- [ ] データベースの変更がある場合、適用の順番を確認している
- [ ] 戻し方を確認している

## 2. リリース

1. `main` の状態を確認する
2. タグを付ける（命名はブランチ運用ルールによる）
3. デプロイを実行する
4. デプロイ完了の表示を確認する

## 3. リリース後の確認

デプロイが完了した表示は、動作の確認ではない。次を必ず実施する。

- [ ] 主要な画面が開く
- [ ] 主要な操作が1つ通る
- [ ] エラーログに新しい種類のエラーが出ていない
- [ ] 秘密情報がブラウザ側に出ていない

## 4. 戻すとき

異常を確認したら、原因の調査より先に戻す。戻したうえで調査する。

戻し方は、平常時に一度試しておくこと。障害の最中に初めて試すことにならないようにする。

## 5. 記録

リリースのたびに、日時、タグ、内容、確認した項目を記録に残す。
