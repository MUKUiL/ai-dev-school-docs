# 障害対応フロー

> 株式会社テックバディ 情報システム部
> ※ 本書は架空の会社の架空の文書です。実在の企業・団体とは関係ありません。

## 1. 検知

障害を検知した者は、まず第一報を出す。原因が分からなくてよい。

第一報に書くこと。

- いつから
- 何が起きているか（利用者から見た症状）
- 影響範囲（分かる範囲で）
- 一報の時点で分かっていないこと

## 2. 役割

| 役割 | やること |
| --- | --- |
| 指揮 | 判断と対外連絡。手を動かさない |
| 調査 | 原因の特定 |
| 記録 | 時刻と実施内容を残す |

1人で3役を兼ねない。人が足りないときは、指揮と記録を優先する。

## 3. 優先順位

復旧が先、原因究明は後。戻せる状態があるなら、まず戻す。

## 4. 顧客への連絡

顧客から「あと何分で戻りますか」と聞かれる。答えられない場合は、答えられないことと、次に連絡する時刻を伝える。連絡の間隔を空けないことが信頼につながる。

## 5. 事後

障害の翌営業日までに、時系列と原因、再発防止策を記録する。個人の責任追及は行わない。手順と仕組みの改善に絞る。
