# ブランチ運用ルール

> 株式会社テックバディ 情報システム部
> ※ 本書は架空の会社の架空の文書です。実在の企業・団体とは関係ありません。

ブランチ名の付け方は開発ガイドラインに定める。ここでは、ブランチの寿命と運用を書く。

## 1. 基本のブランチ

| ブランチ | 役割 |
| --- | --- |
| `main` | 本番に出ている状態。常にデプロイ可能に保つ |
| 作業ブランチ | `main` から切り、`main` へ戻す |

長期間生き続けるブランチを作らない。`develop` のような統合用ブランチは使わない。

## 2. 寿命

作業ブランチの寿命は3営業日を目安とする。それを超えるときは、作業を分割できないかを検討する。

寿命が長いブランチは、`main` の変更を定期的に取り込むこと。取り込みは rebase ではなく merge とし、履歴を書き換えない。

## 3. リリース

リリースはタグで表す。タグ名は `v` に続けて日付とし、同日に複数回リリースする場合は連番を付ける。

```
v2026-08-11
v2026-08-11.2
```

## 4. 本番の緊急修正

`hotfix` は `main` から切り、`main` へ直接戻す。戻したあと、同じ内容が作業中のブランチにも必要かを確認する。

## 5. 削除

マージ済みのブランチは削除する。削除の判断がつかないブランチは、所属長に確認してから残す。
