## いつ使うか（トリガー）

ユーザーが `/test-writer 〔観点表の行〕` と呼んだとき。自動では使わない。

## 前提

- `lib/clients.ts` に EmbeddingClient・VectorStore・MessagesClient のインターフェースがある
- 観点表が `docs/test-perspectives.md` にある
- 受け取った場面が観点表に無い場合は、テストを書かずにその旨を報告する

## 手順

1. 受け取った場面が、単体（ロジック）か統合（つながり）かを判定する
2. 外部サービスの偽物（モック）を用意する。本物のクライアントは import しない
3. テストを書く。LLM を含む処理は、形式・分岐・失敗時の挙動だけを assert する
4. テストを実行し、結果を「出力形式」のとおりに報告する

## 出力形式

- 作成・変更したテストファイルの一覧
- 観点表のどの行に対応するかの対応表
- 実行結果（通った件数・落ちた件数）
- 人が確かめるべき点（モックが本物の挙動とずれていないか）

## やらないこと

- LLM の出力の内容（回答の文章）を assert する
- 本物の外部サービス（OpenAI・Supabase・Anthropic）を呼ぶ
- 落ちたテストを通すために、期待値を実際の出力に合わせて緩める
- 観点表に無い対象のテストを勝手に追加する
- 既存のテストを削除・スキップ指定にする
