# チャンク表 設計書 ── 文書の断片（chunks）

> **このファイルの位置づけ**：文書を分割した「断片」を保存する表の設計です。SQL はここには書かず、次の手順で `schema.sql` に落とします。
>
> **対応する要件**：[`requirements.md`](./requirements.md) の F-1（根拠つき回答）、F-2（根拠が無いときの応答）、F-3（文書の手動取り込み・再取り込み）、3-2 非機能要件。合否の判定は [`spec.md`](./spec.md) を見る。

---

## 1. 保存するもの

文書を分割した「断片」を1行1件で保存する。1行が持つ情報は次の5つ。

1. **どの文書から来たか** ── 断片の元になった文書の名前。回答の根拠として画面に出す
2. **文書の何番目か** ── その文書の中で何番目の断片か。該当箇所の位置を示す
3. **断片の本文** ── 文書から抜き出したテキスト。回答生成のために外部サービスへ送る部分
4. **断片のベクトル** ── 本文を埋め込みモデルで数値化したもの。質問に関連する断片を探すのに使う
5. **いつ入れたか** ── 取り込んだ日時。更新版の反映を確かめる手がかり

---

## 2. 列の定義

| 列 | 型 | 制約 | なぜ（対応する要件） |
| --- | --- | --- | --- |
| `id` | 連番 | 主キー | 1件を特定する。要件番号なし（実装上の識別子） |
| `document` | 文字列 | NOT NULL | 根拠として画面に出す文書名。**F-1 の出力**「根拠となった文書名」。取り込み済み一覧と35件リストの突合にも使う（3-2 セキュリティ「対象文書」、3-4 制約2） |
| `chunk_index` | 整数 | NOT NULL | 文書内の位置。**F-1 の出力**「該当箇所」を示す。`document` との組で断片を一意にし、**F-3** の再取り込み時に二重登録を防ぐ |
| `content` | 文字列 | NOT NULL | 抜粋の本文。**F-1 の処理**「関連箇所をもとに回答を生成する」で生成サービスに渡す部分。外部送信一覧の「送るデータ：取り込み済み文書の関連箇所」に当たる（4-3） |
| `embedding` | ベクトル（次元数は選んだ埋め込みモデルに合わせる） | ── | 検索に使う。**F-1 の処理**「取り込み済み文書から質問に関連する箇所を探す」、および **F-2** の「関連箇所が見つからない」判定の入力 |
| `created_at` | 日時 | NOT NULL・既定は現在時刻 | いつ入れたか。**F-3** の更新版の取り込みが反映されたことの確認、3-2 保守「翌日反映で十分」の確認に使う |

この設計に無い列は追加しない。

## 3. 制約と索引

### 3-1 `document` と `chunk_index` の組を一意にする

| 項目 | 内容 |
| --- | --- |
| 制約 | `(document, chunk_index)` の組み合わせに一意制約を付ける |
| 判断の理由 | 同じ文書を2回取り込んでも、断片が二重に増えない。**F-3**「同じ文書の更新版を取り込んだ場合、更新後の内容を根拠とする」の前提。旧版と更新版の断片が両方残ると、旧版の内容が根拠として返る事故（1回目 情シス「古い情報を教えてしまう」）につながる |
| 注意 | この制約が防ぐのは「同じ位置の断片の二重登録」まで。更新版で断片の数が減った場合、余った旧断片の削除は取り込み処理（F-3）側で扱う。本表では列を足さない |

### 3-2 `embedding` の列に近傍検索用の索引

| 項目 | 内容 |
| --- | --- |
| 索引 | `embedding` に近傍検索（類似ベクトル検索）用の索引を付ける |
| 判断の理由 | **F-1** の「質問に関連する箇所を探す」処理はベクトルの近さで断片を選ぶ。索引が無いと全行との比較になり、3-2 性能（応答時間、目標値は未確認）に影響する |
| 未確認 | 索引の種類と距離関数は、データストアと埋め込みモデルの選定（requirements.md 4-2・5-5 で未確認）に依存する。`schema.sql` を書く時点で決める |

### 3-3 その他の制約

| 列 | 制約 | 理由 |
| --- | --- | --- |
| `document` `chunk_index` `content` `created_at` | NOT NULL | 根拠表示・位置・本文・取り込み日時のどれかが欠けた行は、根拠として画面に出せない |
| `embedding` | 制約なし（設計のとおり） | 設計上、NOT NULL を付けない。埋め込みが無い行は近傍検索で見つからない点に注意する |
| `created_at` | 既定値は現在時刻 | 取り込み処理側で値を渡さなくても記録される |

## 4. 作り直しが必要になる条件

| 条件 | 何が起きるか | やること |
| --- | --- | --- |
| **埋め込みモデルを変えた** | `embedding` の次元数と値の意味がモデルごとに異なるため、旧モデルで作ったベクトルと新モデルのベクトルは混在させられない | `embedding` の列ごと作り直し（次元数を新モデルに合わせる）、近傍検索用の索引も作り直し、**全文書を入れ直す** |

補足：

- 埋め込みモデルの変更は、外部送信一覧（requirements.md 3-2 運用「埋め込み用プロバイダが増える場合も全て記載」）の更新も伴う
- `document` `chunk_index` `content` `created_at` はモデル変更の影響を受けないが、全文書を入れ直す以上、表全体を空にしてから取り込み直すのが前提
