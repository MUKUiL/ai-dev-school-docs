# 質問セット（20問）── 検索品質を測るための材料

> **この文書は根拠の置き場です。**判定に使う基準は [../spec.md](../spec.md) F-2・F-3・5章にある。
>
> **`3-3-8` の品質レポート（型4）は、この20問の結果を材料にして書く。**

| 項目 | 内容 |
| --- | --- |
| 問題数 | **20問**（答えられるべき15問 ＋ 答えられなくてよい5問） |
| 最終更新 | 2026-08-09 |

---

## 1. なぜ質問セットを先に作るのか

**作ってから「どのくらい引けるか」を試すと、引けた質問だけを見て満足します。**

先に20問を固定しておくと、次ができるようになる。

| できること | 理由 |
| --- | --- |
| **改善したかを比べられる** | 分割の大きさを変えたとき、同じ20問で前後を比較できる |
| **答えられない型が見える** | 引けなかった問題に共通する性質が分かる |
| **費用の削減を判断できる** | 根拠を3件→2件に減らしたとき、何問落ちるかが分かる（[cost-estimate.md](./cost-estimate.md) 4章） |

> 📌 **これは `2-2-3` の「検証基準を先に書く」を、検索品質に適用したものです。**

## 3. 答えられなくてよい質問（5問）

**すべて、この構成では原理的に答えられない。**[../spec.md](../spec.md) F-3 の判定に使う。

| # | 質問 | 型 | なぜ答えられないか |
| --- | --- | --- | --- |
| 16 | 今年の経費申請は何件ありましたか | **横断集計** | 個々の文書に「件数」は書かれていない。数えるには全件を集計する仕組みが要る |
| 17 | 就業規則はいつ改定されましたか | **時系列** | 改定履歴が本文に埋もれており、時点の比較ができない |
| 18 | 有給の申請が「不要」なのはどんなときですか | **否定形** | 「不要」と書かれた箇所を探す形になり、書かれていない条件は拾えない |
| 19 | 社員は何人いますか | **対象外の知識** | 対象文書に記載が無い |
| 20 | 来年の賞与はいくらですか | **存在しない情報** | 将来の情報。対象文書にあるはずがない |

> ⚠️ **20問中、16〜20 で1問でも `answer` が返ったら不合格です。**
> クライアントの条件は「間違ったことを自信満々に答えられるのがいちばん困る」でした。**答えられないことを答えられないと返すのが、この案件の合格条件です。**

## 4. 記録の形式

**実行するたびに、次の表を埋める。**

| # | 質問 | 期待 | 結果 | `sources` の妥当性 | 所要秒 | 備考 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 経費の申請期限はいつですか | 回答あり | | | | |
| … | | | | | | |
| 16 | 今年の経費申請は何件ありましたか | **`answer` が `null`** | | ── | | |
| … | | | | | | |

**「`sources` の妥当性」の判定：**

| 判定 | 条件 |
| --- | --- |
| ○ | 示された文書に、実際に答えが書かれている |
| △ | 文書は合っているが、抜粋の箇所がずれている |
| ✗ | 関係の無い文書が示されている |

> 📌 **△と✗を分けて数えてください。**
> △ は分割の設計（重なりの量）で直ることが多く、✗ は検索方式そのものの問題です。**打ち手が違います。**

## 5. 何回測るか

**同じ質問を3回ずつ実行する。**

理由は `1-2-9`・`2-3-9` と同じで、**LLM の出力は毎回変わる**ため。1回ずつの比較は、たまたまの差を結論にしてしまう。

| 記録すること | 理由 |
| --- | --- |
| 3回の結果（○△✗） | ばらつきがあるか |
| **3回とも同じだったか** | 安定しているかどうかが、そのまま信頼できるかどうかになる |

> **3回のうち1回だけ答えが返る**という状態は、**答えが返らないより悪い**ことがあります。利用者は「たまに使える」を信頼できません。品質レポートには、この点を書きます。
