# 質問の文字数の上限・下限を決めた根拠

> **この文書は根拠の置き場です。**判定に使う基準は [../spec.md](../spec.md) 2-1 にある。

| 項目 | 内容 |
| --- | --- |
| 決めた値 | **上限 200 文字／下限 5 文字** |
| 最終更新 | 2026-08-09 |

---

## 1. 測定したもの

**ヒアリングで集めた「実際に Slack で聞かれた質問」29件の文字数を数えた。**

| 統計量 | 値 |
| --- | --- |
| 最小 | 8 文字 |
| 中央値 | 27 文字 |
| 平均 | 34 文字 |
| 最大 | 118 文字 |
| 200文字を超えたもの | **0件** |

**例（架空・実際の記録を模したもの）：**

| 文字数 | 質問 |
| --- | --- |
| 8 | 有給って何日繰り越せる |
| 24 | 経費の申請って月末締めでしたっけ？領収書は原本要りますか |
| 61 | 客先常駐のときの交通費って、定期区間があると引かれるんでしたっけ。あと日跨ぎの深夜手当の扱いも知りたいです |
| 118 | （省略。複数の質問が1つにまとまっていた例） |

---

## 2. 上限を 200 文字にした理由

| # | 理由 |
| --- | --- |
| 1 | 実測の最大が118文字。**中央値の7倍以上**の余裕がある |
| 2 | 200文字を超える入力は、**複数の質問がまとまっている**可能性が高い。1問ずつに分けてもらうほうが検索の精度が上がる |
| 3 | 質問は**毎回ベクトル化される**ので、長さがそのまま費用に乗る（[cost-estimate.md](./cost-estimate.md) 2-2） |

> 📌 **「余裕を持って1,000文字」にしなかった理由。**
> 上限は**大きくするほど安全になるわけではありません。**長い入力を受け付けると、複数の質問が混ざったまま検索することになり、**根拠が分散して F-3（答えを作らない）が増えます。**

---

## 3. 下限を 5 文字にした理由

| # | 理由 |
| --- | --- |
| 1 | 実測の最小が8文字 |
| 2 | 4文字以下（「経費」「有給」など）は**単語であって質問ではない**。検索しても文書全体が広く当たり、根拠が絞れない |
| 3 | 送る前に止められるので、**費用が出ない**（`2-4-13`） |

**下限に当たったときの表示：**「もう少し詳しく書いてください（例：経費の申請期限はいつですか）」

---

## 4. この値を見直す条件

| 条件 | どうするか |
| --- | --- |
| 上限に当たる質問が**月に5件を超えた** | 実際の質問文の長さを測り直す。**上限を上げる前に、複数の質問が混ざっていないかを見る** |
| 下限に当たる入力が**質問の1割を超えた** | 入力欄の説明文を直す。**下限を下げるのは最後の手段** |

> ⚠️ **上限に当たった件数を数えるには、ログに `queryChars` が要ります。**
> [../spec.md](../spec.md) F-6 に入れてあるのはこのためです。**質問文そのものは記録しません。**
