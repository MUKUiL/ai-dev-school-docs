# 議事録要約アプリ 開発ルール

このリポジトリでコーディングエージェントが作業するときのガードレール。
事故の洗い出し（設計図）は [docs/guardrails.md](./docs/guardrails.md)、設定の解説は [docs/procedure/implementation.md](./docs/procedure/implementation.md) にある。

## 仕様

- `docs/spec.md` が**唯一の判断基準**。迷ったら spec.md を参照し、書かれていないことは**推測せず、質問として報告する**。
- `docs/requirements.md` は背景の理解に使う。合否には使わない。
- 数値の根拠は `docs/notes/input-limit.md`（8,000 文字上限）にある。

## 構成のルール

- サーバー側は `app/api/summarize/route.ts` のみ。**API キーと SDK に触れるのはここから呼ばれるコードだけ**。
- `components/` 以下に API キー・`@anthropic-ai/sdk` の import を置かない。
- 部品は `lib/` に置き、1ファイル1責務にする。

## 変更の範囲

- タスクを始める前に、**変更するファイルの一覧**を出す。一覧に無いファイルは変更しない。
- 依頼された範囲を超える変更（似た箇所の一括修正・リファクタ）は、**提案として挙げるだけにして、実行しない**。
- 1タスクで **10 ファイル**を超える変更が必要になったら、止めて分割を提案する。

## 触ってはいけないもの

- **テストの削除**をしない。**期待値を緩めない。**テストが落ちたら、まず実装を疑う。
- `.env`・`.env.local` を読まない、書かない。
- `package.json` の依存を、**理由の説明なしに**追加・変更しない。
- `docs/spec.md` の受け入れ基準を、実装に合わせて書き換えない。

## 検証ループ

- 検証ループの設計は `docs/loop.md` を参照する。
- 各タスクの終わりに `./scripts/verify`（型チェック＋テスト。**ラッパー経由でコンテナ内実行**）を実行し、**緑に戻してから**次へ進む。
- ホストに Node.js や `node_modules` は不要。判定器はコンテナ内で動く。素の `npm run …` をホストで実行しない。
- 依存の再取得が必要なときは `./scripts/install`（**人の承認後**。追加の根拠は spec / PLANS に残す）。
- テストは外部 API を呼ばず、モックで完結させる。

## 確認を挟むこと（実行前に何をするかを述べて、承認を待つ）

- ファイルの削除
- 依存パッケージの追加
- 環境変数・デプロイ設定の変更
- API を呼ぶ回数が増える変更（リトライ回数・並列化。**呼び出し回数の増加は費用の増加** `2-4-10`）

## 停止条件（ここまで来たら手を止めて報告する）

- 同じエラーの修正を **3回**試して直らない
- 仕様（`docs/spec.md`）に書かれていない判断が必要になった
