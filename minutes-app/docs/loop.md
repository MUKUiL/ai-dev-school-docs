# ループ設計 ── 議事録要約アプリ

> **この文書の位置づけ**：実装 → 検証 → 修正のループを回すための設計（`2-1-2` のハンズオンで作る）。**何で判定するか（判定器）・機械で判定できないものをどこで人が見るか・いつ止めるか**の3枠で定義する。
> ガードレール定義（禁止・確認・停止）は [guardrails.md](./guardrails.md)。エージェント向けの運用ルールへの変換先は [CLAUDE.md](../CLAUDE.md)「検証ループ」にある。**この文書を直したら、変換先も直す。**

## 判定器

| # | 判定器 | コマンド | 何を判定するか |
| --- | --- | --- | --- |
| 1 | 型チェック＋テスト | `./scripts/verify` | 型の辻褄と、決めた振る舞い（テストは外部 API を呼ばず、モックで完結） |
| 2 | ビルド | `docker compose run --rm app npm run build` | 動く形になっているか |

- 判定器は**コンテナ内で実行**する（ホストに Node.js は不要）。入口はラッパー `./scripts/*` に統一する。
- 判定器を足すときは、この表に行を足す。**1コマンドで回せる形を崩さない**（Lint を足すなら `verify` に連結する）。

## 人が見る場所（機械で判定できないもの）

| # | 見る場所 | 見つけ方の手順 |
| --- | --- | --- |
| 1 | 変更範囲 | `git diff --stat` を見て、頼んでいないファイルが変わっていないか確かめる |
| 2 | テストの件数 | `./scripts/verify` の出力で、件数が作業前より減っていないか確かめる（期待値の緩和・テスト削除の検知） |
| 3 | 画面の崩れ | 上限いっぱい（8,000 文字）の議事録と、改行を含まない長い1行を貼り、ボタンが画面外に出ないか・押せるかを見る |
| 4 | 出力のばらつき | 同じ議事録を複数回流し、形式（要約の行数・アクション項目のフィールド）が揃っているかを見る（`2-4-13` で扱う） |

## 打ち切り条件

| # | 条件 | 打ち切ったあと何をするか |
| --- | --- | --- |
| 1 | 同じ症状への修正が **3回** を超えた | 直前のコミットに戻し、症状の記述からやり直す（`1-2-7` の4ステップ） |
| 2 | 1つの症状に **30分** を超えた | 範囲を1ファイルに絞って依頼し直す |
| 3 | 1回の依頼で **10ファイル** を超えて変わった | 依頼を分割する |
