# 入力の上限を 8,000 文字とした根拠

> この文書は**補足資料**です（`2-2-5`）。仕様書の本文には決定（8,000 文字）だけを置き、
> 測定の記録はこちらに逃してあります。

## 測定

1時間程度の会議の議事録を想定し、想定される長さを見積もった。

| 想定 | 文字数の目安 |
| --- | --- |
| 30分・参加者4名の定例 | 1,500〜2,500 |
| 1時間・参加者6名の設計会議 | 3,000〜5,000 |
| 2時間・参加者10名の合同会議 | 6,000〜8,000 |

## 8,000 にした理由

- 上の想定の最大側（2時間規模）を収められる
- 日本語は 1文字 ≒ 1トークン前後なので、入力トークンは約 8,000。
  システムプロンプト（約 400 文字）を足しても、1回の入力は1万トークン未満に収まる
- これ以上を許すと、1回あたりの費用と所要時間が跳ね上がり、
  仕様の「10秒以内」（F-2）を満たしにくくなる

## 上限を超えたときの扱い

**送信前に止める。**（`2-2-4` の 2-3 の異常系②）
外部を呼んでから気づくと、時間も費用もかかる。
