# ガードレール定義 ── 議事録要約アプリ

> **この文書の位置づけ**：このプロジェクトで起こりうる事故を先に洗い出し、**禁止事項・確認ポイント・停止条件**の3枠で定義したもの（`2-1-1` のハンズオンで作る設計図）。
> これは「言葉」の段階であり、実行可能な形への変換先は [CLAUDE.md](../CLAUDE.md) と [.claude/settings.json](../.claude/settings.json) にある（`2-5-15`）。**この文書を直したら、変換先も直す。**
>
> 層の記号：**①設定**（実行される前に止める）／**②プロセス**（人が見る場所を決める）／**③コード**（実行した直後に機械が検知する）

## 禁止事項（やらせないこと）

| # | 禁止すること | 防ぐ事故 | 層 |
| --- | --- | --- | --- |
| 1 | ファイルの削除コマンドを自動実行させない | 「整理して」で必要なファイルが消える | ① |
| 2 | `.env` と鍵ファイルを読ませない | API キーが会話とログに残る | ① |
| 3 | API キーをフロントエンドのコードに書かせない | 公開ページから鍵が読める | ①③ |
| 4 | 指示していないライブラリを追加させない | 説明できない依存が増える | ①② |
| 5 | 落ちたテストを削除・期待値の緩和で通させない | 欠陥がテストごと消える | ②③ |

## 確認ポイント（人が必ず見る場所）

| # | 見る場所 | なぜ人が見るか |
| --- | --- | --- |
| 1 | `git diff --stat` ── 変更されたファイルの一覧 | 頼んでいない場所が変わっていないかは、機械では判定できない |
| 2 | `package.json` の差分 | 依存が増えていないか。増えているなら理由を聞く |
| 3 | API を呼ぶ箇所（`lib/summarize.ts`・`lib/retry.ts`） | 呼ぶ回数と、失敗したときの動きは目で確かめる。**呼び出し回数の増加は費用の増加**（`2-4-10`） |

## 停止条件（ここまで来たら手を止める）

| # | 条件 | 止めたあと何をするか |
| --- | --- | --- |
| 1 | 同じエラーの修正を **3回** 試して直らない | 直前の状態に戻し、症状の記述からやり直す（`1-2-7` の4ステップ） |
| 2 | 1つの依頼で変更が **10ファイル** を超えた | 依頼を分割する。範囲が広すぎる |

**「言葉」のままでは効かない。**それぞれ、どの仕組みに変換したかの対応表。
